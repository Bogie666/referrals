# LEX Referral App — Agent Notes

## Launch-day reminder (READ THIS)

If the user says they're ready to go live (or anything similar — "let's launch", "we're going live now", "time to flip the switch"), **before doing anything else, remind them to do these three steps in order**:

1. **Run `sql/launch-cleanup.sql`** in the Supabase SQL editor. It wipes the test-poll ghost rows (customers, referrals, payouts, texts_log, job_events) and resets `poll_state.last_polled_at` to today's midnight Central Time. Confirm the after-counts are all zero.
2. **Set `DEMO_MODE=false`** (or delete the env var) in Vercel → Settings → Environment Variables, then trigger a redeploy. Without this, the cron will still run but every Chiirp text and every ServiceTitan write-back will be intercepted by the demo wrapper and nothing real will happen.
3. **Let the cron take over.** Poller runs every hour at :00 UTC (`0 * * * *`). If launch is mid-hour, the user can manually fire `curl https://lexperks.com/api/cron/poll-jobs -H "x-cron-secret: $CRON_SECRET"` to start without waiting.

Until those three steps are done, the system is in demo mode and won't actually enroll anyone or send anything to real customers.

## Project orientation

- **Vercel app** at `lexperks.com` — Express server (admin dashboard, API, /book, /share, /referral redirect, /api/cron/poll-jobs). The customer portal ALSO lives here at `/share/:code` and `/my-referrals` as a fallback / deeplink target, but the primary customer-facing portal is the WordPress shortcode below.
- **WordPress site** at `lexairconditioning.com` — hosts the customer portal via the `[lex_referral_portal]` shortcode from `wordpress/lex-perks.php` (currently Version 2.0.0). Also provides the `[lex_referral]` friend-landing shortcode. The plugin file must be re-uploaded manually to WP after any edit — it is NOT deployed by Vercel. Bump the `Version:` header in the plugin doc-block whenever you change anything so WP will treat it as an update. When touching share features, portal stats, or eligibility badges in the Node portal (`src/routes/share.js`), consider whether the WP shortcode needs the same change — the two portals have drifted before.
- **Supabase** — Postgres DB (customers, referrals, payouts, system_settings, etc.). Service-role key in `SUPABASE_SERVICE_KEY`.
- **ServiceTitan** — source of truth for jobs/customers. Polled hourly via Vercel cron (`0 * * * *`) by `src/routes/cron.js`. Two custom fields are in play and they live on DIFFERENT records:
  - `406119043` "Referral Code" — on the **CUSTOMER** record. Their personal code, generated by us and PATCHed back via `writeReferralCodeToCustomer`.
  - `406119323` "Referred by Code" — on the **JOB** record. The code of the person who referred them, set by CSRs at booking or by the online scheduler. Read via `getJobCustomFields(token, jobId)` because the JPM v2 jobs list endpoint doesn't reliably return customFields inline.
- **Chiirp** — webhook-driven SMS + email automation. URL in `CHIIRP_WEBHOOK_URL`. Payload uses `phone_number` and `email_address` (renamed from `phone`/`email` — the campaign expects these exact keys).

## Payout rule (current)

`payout_amount = min(invoice_total * payout_percentage / 100, payout_cap)`. Default 5% capped at $250. No special case for memberships (the original $25 flat for membership-only invoices was retired in commit `72be433`). Configured in `system_settings` and editable in `/admin/settings`.

## Referral code format

6 chars from a 32-char unambiguous alphabet (no 0/1/I/O/L). Generated in `src/utils/slugs.js generateUniqueReferralCode`, written to ServiceTitan custom field 406119043 by the poller, used in URLs as `lexperks.com/referral?r=CODE`. Lookups normalize input via `normalizeCode()` so dashes/spaces/case don't matter.

## Eligibility filters (enrollment only)

These gate which customers get enrolled. They do NOT affect referral matching — a friend's job credits the referrer regardless.

- `residential_only` (default `true`) — skip ST customers whose `type !== 'Residential'`.
- `excluded_business_unit_ids` (default `6540, 7698, 7832, 7949, 8087`) — comma-separated ST business unit IDs. Jobs in these BUs don't trigger enrollment.

Both editable in `/admin/settings → Eligibility Filters`.

## Safety rails

- `max_lookback_hours` in `system_settings` (default 24) caps how far back the poller can reach regardless of `poll_state.last_polled_at`. Protects against another "process the entire backlog" surprise.
- Per-poll cap of 500 jobs (hardcoded in `getCompletedJobs`) is a second line of defense.
- `DEMO_MODE=true` short-circuits all Chiirp sends and ServiceTitan writes — nothing leaves the system.

## Common pitfalls

- `wordpress/lex-perks.php` IS live — it's the customer portal on `lexairconditioning.com` via `[lex_referral_portal]`. Vercel does not deploy it; user re-uploads the file to WP after edits. Bump the `Version:` header when you change it.
- The WP portal and the Node `/share/:code` portal have drifted. Features added to `src/routes/share.js` (tracking beacons, share-event beacon, portal_view beacon, payout-eligibility badge, active-referral count, "in flight" callout, etc.) may or may not exist in the WP shortcode — check both when consistency matters.
- The external scheduler at `scheduler-mu-three.vercel.app` is responsible for setting custom field 406119323 ("Referred by Code") on the friend's ST **job** record at booking time (NOT the customer record — that was a long-standing doc bug). If matches are coming up empty, verify the scheduler is PATCHing the job, not the customer.
- `CRON_SECRET` rotation requires a Vercel redeploy to pick up.
